# 共有ドライブQA — RAGシステム

社内共有ドライブ（未加工のフォルダ・ファイル群）と質問文のみを入力として、
質問に対する回答を自動生成する RAG パイプライン。

質問固有の答え・参照ファイル・ページ番号・セル番地などは一切コードに書かれていない。
案件略称、パスワード導出規則、決裁基準といった「社内ルール」も、実行時に共有ドライブ内の
該当文書を読んで解決している。未知の案件フォルダ・未知の資料が追加されても同じ処理で動く。

## コンペ規約への適合（`evaluation/readme.md`「禁止される処理」との対応）

| 禁止事項 | 本実装 |
|---|---|
| 人手で整理した独自DB・一覧表を読み込ませる | 入力は未加工の共有ドライブのみ。中間表現（抽出JSON・BM25索引・画像レジストリ）は実行時に生成され、`--force` で再生成される |
| 質問ごとの正解候補・参照ファイル・重要ページ等を事前にまとめたファイル | 存在しない。質問文はエージェントへの入力としてのみ使う |
| 特定質問の答え・金額・担当者名・ページ番号・セル番地をコードやプロンプトに書く | 書いていない（下記の監査コマンドで検証可能） |
| 質問文・record_id を見て固定回答を返す | 質問文による分岐は一切ない。全問が同一のエージェントループを通る |
| 案件名・ファイル名を見た専用分岐 | ない。案件はフォルダ探索と用語集で解決し、形式ごとの汎用処理のみ |
| 人が資料を開いて回答を作る／GUIツールに1問ずつ入力 | 回答生成は `run.py` の自動実行のみ |
| 個別設問の正解を人手で確認してルール・プロンプトに反映 | 検証セットは抽出器の動作確認にのみ使用。正解値をコード・プロンプトに反映していない |
| 資料を読まず外部知識・推測で回答 | プロンプトで根拠必須を指示し、確証がなければ「確認できませんでした」を返す |
| 外部Web検索の結果を根拠に使う | ネットワークアクセスは LLM API のみ。検索ツールを持たせていない |

監査用コマンド（案件名・金額・人名・ID の直書きが無いことの確認）:

```bash
grep -rnE "案件名|略称|[0-9]{1,3},[0-9]{3},[0-9]{3}" rag --include=*.py | grep -v rag/tools/
```

`rag/tools/` は診断・調査用スクリプトで、回答生成では読み込まれない。

## 「実装方法」要件への対応

| 要件 | 対応 |
|---|---|
| 未加工の共有ドライブと質問文のみを入力 | `corpus.py` は `共有ドライブ/` のみを走査。正解を含む `質問回答/` はコーパス・索引ともに非対象（`selfcheck` で検証）。エージェントへの入力は質問文1行のみ |
| 実行時に汎用処理で読み取り・抽出・検索 | 形式別の汎用パーサ＋BM25。事前生成物は `--force` で全再生成される |
| 未知の案件・資料・質問でも同じ処理 | 案件はフォルダ走査で列挙し、用語集に無い案件はフォルダ名で登録するフォールバックあり。質問はCSVの `index,question` のみに依存 |
| 特定質問の答えを暗記しない | 質問文による分岐・固定回答表なし |
| 複数資料・複数案件にまたがる検索照合集計 | `each_text()` で全案件を一括走査、`run_python` で集計 |
| 社内用語・略称は用語集を参照 | `lookup_glossary` が実行時に用語集を解析して解決 |
| 形式・単位・小数桁・丸め方の遵守 | システムプロンプトで明示指示 |
| 該当なしの場合はその旨回答 | 同上 |
| 略称ではなく通常表現で回答 | 同上（設問が略称指定の場合を除く） |
| 資料内の識別子は表記どおり | 同上 |
| 再現可能・再実行で同等の回答 | temperature=0、OpenAI では `seed` を送信、全応答をリクエストハッシュでディスクキャッシュ。解析サンドボックスも `random`/`numpy` のシードを固定 |
| 前処理＋100問が12時間以内 | 前処理は実測 約6分（抽出168秒＋画像レジストリ＋索引）。画像書き起こしと回答生成はAPI速度依存のため `--workers` で並列度を調整可能。所要時間は `artifacts/logs/run_*.json` に実測記録 |
| seed固定・ログ保存・モデル名記録 | `artifacts/logs/run_*.json` にモデル名・プロバイダ・seed・temperature・並列度・所要時間・ツール呼び出し総数を記録。`artifacts/answers/*.json` に設問ごとの回答・根拠・**全ツール呼び出し履歴**を保存 |
| 1回答あたり1000トークン以内 | `run.py` の `truncate_tokens()` で提出前に切り詰め |

## 構成

```
rag/
  config.py       パス解決（共有ドライブのルートを名前に依存せず探索）
  corpus.py       全ファイルを形式別に構造化抽出 → artifacts/docs, artifacts/text
  glossary.py     社内用語集を実行時にパースし、略称→正式名称／案件を解決
  images.py       画像レジストリ（図・画像PDFページ・ノートブック出力・スライド描画）
  vision.py       画像をLLMで書き起こし → artifacts/vision.json（キャッシュ）
  index.py        チャンク分割 + BM25（日本語は文字バイグラム）
  agent.py        ツール使用エージェント（本体）
  pysandbox.py    モデルが書いた集計コードを別プロセスで実行
  llm.py          プロバイダ抽象（OpenAI互換 / Anthropic）+ 全応答をディスクキャッシュ
  run.py          質問ファイルを回答 → submit/predictions.csv, submission.zip
  score.py        検証用：コンペと同じCRAG基準で自己採点
  dax/            形式別エクストラクタ
    docx_ex.py    段落/表/コメント/書式(太字・下線・色・ハイライト)/埋め込みグラフ
    pptx_ex.py    スライド/図形(座標・塗り)/表/グラフ/ノート/書式
    xlsx_ex.py    セル値・数式と計算結果・塗り色・オートフィルタ・ピボット・条件付き書式・グラフ
    pdf_ex.py     ページ単位テキスト・表・注釈、画像ページ判定、ページ画像化
    nb_ex.py      ノートブックのソースと出力（テキスト・画像）
    chart_ex.py   DrawingMLチャートの系列・カテゴリ・実値・軸目盛・系列色
    text_ex.py    CSV/TSV（プロファイル）・JSON・コード・テキスト
    com_render.py Office→PDF変換（ページ番号の実測とページ画像化）
    unlock.py     保護ファイルのパスワードを規則から導出して復号
    util.py       正規化・色分類・OOXML共通処理
```

## 設計上の要点

**Unicode正規化** — 配布データのフォルダ名は NFD 正規化されている（`ド` = `ト`+濁点）。
パスをリテラルで書くと一致しないため、探索は常に正規化して行う。

**書式は情報である** — 「黄色ハイライト」「太字」「オレンジの行」を問う質問が多いため、
抽出テキストには書式をインラインタグ（`[[bold]]…[[/]]`、`[[hl:yellow]]…[[/]]`）として残す。
色は色相で分類し、淡い地色は `pale-` を付けて装飾と強調を区別できるようにしている。
Excel は色ごとの使用セル数と対象行も併記し、「少数派の色＝ハイライト」を判断できるようにした。

**ページ番号は実測** — Word のページ送りはレイアウト時に決まるため、OOXML からは分からない。
インストール済みの Office（なければ LibreOffice）で PDF 化し、実際のページ割りを取得する。
`locate_in_pages` ツールが表記ゆれ（PDF出力時に入る空白など）を無視して照合する。

**グラフは実値** — チャートパートには全プロット点がキャッシュされている。
「x=3 のときの y」「青い折れ線」といった質問に、画像を目視せず厳密に答えられる。
系列のテーマ色は実RGBに解決してから色名を付けている。

**画像は機械OCRして本文として扱う** — 画像PDF（テキスト層なし）、図表PNG、ノートブック出力、
座席表は、視覚モデルで書き起こして本文と同様に検索・読解の対象にする。この工程は他の抽出工程
（表抽出・書式抽出・シート読取）と同じ機械処理であり、次の性質を満たす。

- 質問文を一切参照しない。全画像を登録順に、単一の固定プロンプトで同一処理する
- 未加工の共有ドライブから再生成できる（`vision.py` を再実行するだけ）
- 出力は「見えているものの転記」であり、正解候補・参照先・重要ページの一覧ではない
- 人手による編集は介在しない

`artifacts/vision.json` は同じ画像を二度処理しないためのキャッシュであって、
事前に用意しておかないと動かない入力ファイルではない。

**計算はコードで** — 相関・群平均・しきい値最適化・日数計算などはモデルに暗算させず、
`run_python` で pandas を実行して求める。

**保護ファイル** — パスワードも、その**書式**もコードに書いていない。
保護ファイルは他の全ファイルの後に処理し、その時点で読めている共有ドライブ本文から
「パスワード」に言及する文書を拾い、`PREFIX-[プレースホルダ]-…` 形式のテンプレートと記載例を
実行時にパースする。プレースホルダは、用語集由来の案件略称と、当該案件の文書中に現れる日付で
埋め、復号に成功した候補を採用する。ファイル名が持つヒント（`_pw-xxxx`）も候補に含める。
規則文書が存在しない場合は、名前のヒント以外は推測せずに諦める。

**再現性** — LLM 応答は要求内容のハッシュをキーにディスクキャッシュ。temperature=0。
使用モデル・シード・ツール呼び出し履歴を `artifacts/logs`, `artifacts/answers` に記録する。

## 実行手順

```bash
pip install -r rag/requirements.txt

# 1. 抽出（全ファイル）— 約9分（Office変換込み、2回目以降はキャッシュで高速）
python rag/corpus.py

# 2. 画像レジストリ
python rag/images.py

# 3. 検索インデックス
python rag/index.py

# 4. 画像の書き起こし（LLM）
python rag/vision.py

# 5. 回答生成 → submit/predictions.csv, submit/submission.zip
python rag/run.py --questions test

# 検証セットで自己採点する場合
python rag/run.py --questions valid
python rag/score.py --questions valid
```

## モデルの設定

環境変数で選ぶ。`OPENAI_BASE_URL` が設定されていればそれが最優先。

| 構成 | 設定 |
|---|---|
| OpenAI | `OPENAI_API_KEY=sk-...` |
| Anthropic | `ANTHROPIC_API_KEY=sk-ant-...` |
| ローカル / ゲートウェイ | `OPENAI_BASE_URL=http://localhost:8000/v1` ＋ `RAG_MODEL=<モデル名>` |

モデルには **画像入力** と **ツール呼び出し** の両方が必須。次で確認できる。

```bash
python rag/tools/check_llm.py
```

### ローカルLLMで動かす

OpenAI互換エンドポイントを出せる実行基盤（vLLM / Ollama / LM Studio）ならそのまま使える。
API キーは不要（未設定ならダミーが使われる）。ローカル判定時は `parallel_tool_calls` を
無効化する — 開いたモデルは複数ツールの同時発行で崩れやすいため。

vLLM（WSL2 + CUDA）の例:

```bash
pip install vllm
vllm serve Qwen/Qwen2.5-VL-7B-Instruct \
    --max-model-len 32768 --limit-mm-per-prompt image=2 --port 8000
```

Ollama（Windows ネイティブ）の例:

```bash
ollama pull qwen2.5vl:7b
# エンドポイントは http://localhost:11434/v1 、RAG_MODEL=qwen2.5vl:7b
```

いずれの場合も Windows 側から:

```powershell
$env:OPENAI_BASE_URL = "http://localhost:8000/v1"
$env:RAG_MODEL       = "Qwen/Qwen2.5-VL-7B-Instruct"
python rag/tools/check_llm.py
```

WSL 上のサーバに Windows から繋ぐ場合、`--host 0.0.0.0` で起動し、
`http://<WSLのIP>:8000/v1`（`wsl hostname -I` で確認）を指定する。
